13.1Why dynamic programming?

Dynamic programmingSolve subproblems once, store their answers, and reuse those answers whenever the same subproblem reappears.
Overlapping subproblems

The recursion repeatedly asks for identical states, such as F(3) or KP(i,W).

Optimal substructure

An optimal solution can be constructed from optimal solutions of smaller states.

A DP solution is a dependency graph of states. The recurrence specifies the incoming dependencies; memoization or tabulation determines how the graph is evaluated. Correctness comes from showing that the recurrence covers every valid possibility and combines already-correct smaller answers.

When DP gives no benefitFactorial has no repeated subproblem in one evaluation, and merge-sort subproblems are disjoint rather than identical. DP is therefore not useful for a single n! or for ordinary merge sort.

13.2Fibonacci: recursion versus DP

def fibonacci(n):
    if n == 0: return 0
    if n == 1: return 1
    return fibonacci(n-1) + fibonacci(n-2)

Throughout this chapter, use zero-based indexing: F(0)=0, F(1)=1, and F(n)=F(n−1)+F(n−2). Therefore F(9)=34 and F(10)=55. Naive recursion evaluates the same states repeatedly; its running time is Θ(φn), where φ=(1+√5)/2. Memoization evaluates each distinct state once.

Memoized Fibonacci · F(5)

Follow the actual left-to-right recursion: call, cache, and reuse.

Why the improvement is linearThere are n+1 states, F(0) through F(n). Each non-base state performs one addition after obtaining its two dependencies. Under the standard unit-cost arithmetic model, this gives O(n) time. Memoization also uses an O(n) recursion stack; the rolling-pair iterative version uses O(1) auxiliary space.
Θ(φⁿ)plain Fibonacci recursion; O(2ⁿ) is a valid loose bound
O(n)memoized/table time
O(n)table space

13.3Top-down and bottom-up DP

Top-down · memoization

Start from the requested input. Recurse only when a needed answer is absent; otherwise return the cached value.

def fib(n, memo):
    if n < 2: return n
    if memo[n] == -1:
        memo[n] = fib(n-1,memo)+fib(n-2,memo)
    return memo[n]
Bottom-up · tabulation

Start with the smallest states, then build solutions for increasing input values.

def fib(n):
    if n < 2: return n
    dp = [0] * (n+1)
    dp[1] = 1
    for i in range(2,n+1):
        dp[i] = dp[i-1] + dp[i-2]
    return dp[n]
Space optimizationKeep only prev2 and prev1. Each new Fibonacci number replaces the older pair, reducing auxiliary space from O(n) to O(1). For an acyclic dependency graph, both approaches implement the same recurrence. Choose an order in which every dependency is available before its dependent state.

13.40/1 knapsack

Each item is either included once or excluded. For item i and current capacity Wc, define KP(i,Wc) as the maximum profit using items 1…i.

There are exactly two choices for item i: exclude it and retain capacity w, or include it and leave capacity w−wi. In both cases, only items 1…i−1 remain available. Taking the maximum covers all feasible subsets. The base case assumes positive item weights, so a zero-capacity knapsack earns zero.

Why greedy profit/weight failsCapacity 15; item 1 has profit 5 and weight 1 (ratio 5), item 2 has profit 15 and weight 15 (ratio 1). Greedy selects item 1 and earns 5, but the optimal 0/1 choice is item 2 with profit 15.
KP(i,Wc) = 0 if i=0 or Wc=0
KP(i,Wc) = KP(i−1,Wc) if wi > Wc
otherwise max(pi + KP(i−1,Wc−wi), KP(i−1,Wc))
O(2ⁿ)brute-force include/exclude tree
O(nW)DP time
O(nW)2D table space
Assumptions and complexityWeights and capacity are nonnegative integers, and item weights are strictly positive. O(nW) is pseudopolynomial: it depends on the numeric capacity W, rather than the number of bits used to encode W. A one-dimensional table uses O(W) space; process capacities in decreasing order to preserve the 0/1 constraint.

13.5Building the knapsack table

Worked example: four items have profits [1,2,5,6] and weights [2,3,4,5], with capacity W=8. State KP(i,w) uses only the first i items and capacity at most w. Each transition reads the previous row, preventing an item from being selected twice.

Bottom-up 0/1 knapsack

Watch each state compare “exclude” with “include”.

Read one transitionAt KP(4,8), excluding item 4 gives KP(3,8)=7. Including it gives 6+KP(3,3)=6+2=8. Therefore store 8. To recover the subset, compare each cell with the cell above: a strictly larger value means this traceback takes the current item and subtracts its weight.
profit = [0, 1, 2, 5, 6]
weight = [0, 2, 3, 4, 5]
kp = [[0] * (W + 1) for _ in range(n + 1)]
for i in range(1, n + 1):
    for w in range(1, W + 1):
        if weight[i] <= w:
            kp[i][w] = max(profit[i] + kp[i-1][w-weight[i]], kp[i-1][w])
        else:
            kp[i][w] = kp[i-1][w]
return kp[n][W]
Top-down memoized version
def knapsack(i, capacity):
    if i == 0 or capacity == 0: return 0
    if memo[i][capacity] != -1: return memo[i][capacity]
    result = knapsack(i-1, capacity)
    if weight[i] <= capacity:
        result = max(result, profit[i] + knapsack(i-1, capacity-weight[i]))
    memo[i][capacity] = result
    return result

13.6Matrix multiplication order matters

Multiplying an m×n matrix by an n×p matrix produces an m×p matrix and uses mnp scalar multiplications.

A1: 2×3, A2: 3×4, A3: 4×5
A1(A2A3): 3·4·5 + 2·3·5 = 60 + 30 = 90
(A1A2)A3: 2·3·4 + 2·4·5 = 24 + 40 = 64

Matrix multiplication is associative, so parenthesization changes the work, not the mathematical product. The matrix sequence remains fixed: A₁A₂A₃ is not reordered. This chapter counts classical scalar multiplications and assumes compatible dimensions.

For four matrices there are five parenthesizations: A1(A2(A3A4)), A1((A2A3)A4), (A1A2)(A3A4), (A1(A2A3))A4, and ((A1A2)A3)A4. DP chooses the least-cost order without enumerating every full multiplication.

13.7Matrix-chain dynamic programming

Statem[i,j] is the minimum scalar-multiplication cost for matrices Ai…Aj. The diagonal m[i,i]=0.

Every parenthesization has a final split k: multiply the result of Ai…Ak by the result of Ak+1…Aj. Their dimensions are p[i−1]×p[k] and p[k]×p[j]. The cost is the best cost of each subchain plus the cost of this final multiplication. Try every legal k and retain the cheapest.

m[i,j] = mini≤k<j{m[i,k] + m[k+1,j] + p[i−1]p[k]p[j]}

Fill by increasing chain length

Dimensions p=[2,3,4,5,2].

def matrix_chain_order(p):
    n = len(p) - 1
    m = [[0]*(n+1) for _ in range(n+1)]
    s = [[0]*(n+1) for _ in range(n+1)]
    for length in range(2, n+1):
        for i in range(1, n-length+2):
            j = i + length - 1; m[i][j] = float('inf')
            for k in range(i, j):
                q = m[i][k] + m[k+1][j] + p[i-1]*p[k]*p[j]
                if q < m[i][j]: m[i][j], s[i][j] = q, k
    return m, s

The split table s[i,j] stores the k that achieved the minimum. Reconstruct the order recursively by splitting at s[i,j] until each subchain contains one matrix. There are O(n²) intervals and at most O(n) splits per interval, giving O(n³) time.

O(n³)time
O(n²)m and s tables
76optimal cost for all four matrices
Optimal orderA1(A2(A3A4)): first A3A4 costs 40, then A2(A3A4) costs 24 more, and the final multiplication costs 12; total 76.

13.8Rod-cutting problem

Prices for lengths 1…10 are [1,5,8,9,10,17,17,20,24,30]. For a rod of length n, choose the first piece i and combine its price with the best revenue for n−i.

Assume integer lengths, a listed price for every supported piece length, and no cutting cost. The whole rod must be sold. Choosing i=n sells the rod intact; choosing a smaller i leaves a remainder whose optimal revenue is r[n−i]. Piece lengths may be reused, unlike items in 0/1 knapsack. Set r[0]=0.

rn = max{pn, r1+rn−1, …, rn−1+r1} = max1≤i≤n{pi+rn−i}

Bottom-up revenue construction

Every possible first cut is tested for each increasing rod length.

Why cutting can earn moreFor length 4, selling intact earns 9. Cutting into 2+2 earns 5+5=10, which is optimal. For length 8, the first-cut choice 2 leaves length 6: 5+r[6]=5+17=22. Store the best first piece for each length, then repeatedly subtract it to recover a complete decomposition.
n12345678910
r[n]15810131718222530
best decomposition1232+22+361+6 or 2+2+32+63+610
Naive recursion
def cut_rod(p,n):
    if n == 0: return 0
    q = float('-inf')
    for i in range(1,n+1):
        q=max(q,p[i]+cut_rod(p,n-i))
    return q

T(n)=1+Σj=0n−1T(j), exponential time.

Bottom-up
def bottom_up_cut_rod(p,n):
    r=[0]*(n+1)
    for j in range(1,n+1):
        q=float('-inf')
        for i in range(1,j+1):
            q=max(q,p[i]+r[j-i])
        r[j]=q
    return r[n]

O(n²) time and O(n) space.

Memoized top-down rod cutting
def memoized_cut_rod(p,n):
    r=[float('-inf')]*(n+1)
    def aux(length):
        if r[length] >= 0: return r[length]
        if length == 0: q=0
        else: q=max(p[i]+aux(length-i) for i in range(1,length+1))
        r[length]=q; return q
    return aux(n)

13.9Longest common subsequence (LCS)

Given two sequences X and Y, find the longest sequence that appears in both in the same relative order. Characters may be skipped, but they may not be rearranged. LCS measures agreement between sequences and is a useful foundation for comparing text and explaining insertion/deletion edits.

Subsequence: gaps are allowed

ACE is a subsequence of ABCDE: retain A, C, and E and skip B and D. A subsequence preserves order; CA is not a subsequence of ABCDE.

Substring: characters are consecutive

BCD is a substring of ABCDE. ACE is not. The LCS recurrence below solves the subsequence problem; the longest common substring problem needs a different recurrence.

Define the state using prefixes

State and base casesL[i,j] is the length of an LCS of X[0:i] and Y[0:j], the first i and j characters. Set L[0,j]=L[i,0]=0: an empty sequence has no nonempty common subsequence.
If X[i−1] = Y[j−1]: L[i,j] = 1 + L[i−1,j−1]
Otherwise: L[i,j] = max(L[i−1,j], L[i,j−1])

When the last characters match: an optimal common subsequence can end with that character. Append it to an LCS of the two shorter prefixes. This explains the diagonal dependency and the added 1.

When the last characters differ: they cannot both be the final matched character. Every common subsequence omits at least one of those two positions, so compare the solution that drops X’s last character with the solution that drops Y’s last character. Choose the longer result.

Fill the table row by row, from left to right. Each state uses only the cell above, the cell to the left, or the diagonal cell, all of which are already available. The final length is L[m,n], where m=len(X) and n=len(Y).

Match, compare, and reconstruct

X = ABCBDAB · Y = BDCABA. Build the table, then follow an optimal path backwards.

Recover the sequence, not just its length

  1. Start at L[m,n]. If the current characters match, record that character and move diagonally up-left.
  2. If they differ, move to whichever of the upper or left cells has the larger value. Either direction is valid when the values tie; here we choose up.
  3. Stop when either prefix becomes empty. Reverse the recorded characters because the walk collected them from right to left.
Worked resultFor ABCBDAB and BDCABA, the LCS length is 4. The up-on-ties rule returns BCBA. Its positions are 2, 3, 4, 6 in X and 1, 3, 5, 6 in Y (positions here are one-based). BDAB and BCAB are also valid LCS answers: an optimal length does not imply a unique sequence.
def longest_common_subsequence(x, y):
    m, n = len(x), len(y)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if x[i - 1] == y[j - 1]:
                dp[i][j] = 1 + dp[i - 1][j - 1]
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

    i, j = m, n
    result = []
    while i > 0 and j > 0:
        if x[i - 1] == y[j - 1]:
            result.append(x[i - 1])
            i -= 1
            j -= 1
        elif dp[i - 1][j] >= dp[i][j - 1]:
            i -= 1
        else:
            j -= 1
    return dp[m][n], ''.join(reversed(result))
O(mn)table construction time
O(mn)space for the table and traceback
O(m+n)traceback time after table construction
Space optimization and its tradeoffIf only the length is needed, keep two rows and use O(min(m,n)) auxiliary space by placing the shorter sequence along the columns. Ordinary traceback requires the full table. Recovering a sequence in linear space needs a more advanced method, such as Hirschberg’s algorithm.

LCS practice problems with explanations

Problem 1 · Trace a small table

Find an LCS of X=ABC and Y=AC. Write the final row of the DP table, including the empty-prefix column.

Show solution

The final row is [0,1,2], and the LCS is AC. Matching A creates length 1; B contributes no match; matching C extends the diagonal prefix result to 2. The B in X can be skipped because a subsequence need not be contiguous.

Problem 2 · A standard worked example

Find an LCS of X=AGGTAB and Y=GXTXAYB. Explain why the answer is valid.

Show solution

The length is 4 and an LCS is GTAB. It appears at positions 2,4,5,6 in X and 1,3,5,7 in Y. The DP recurrence gives L[6,7]=4, establishing that no common subsequence is longer.

Problem 3 · Multiple optimal answers

Find all distinct LCS strings of X=ABC and Y=BAC. Does one traceback necessarily find all of them?

Show solution

The length is 2. The distinct answers are AC and BC. One traceback chooses one branch when the table values tie, so it returns only one answer. To enumerate all answers, follow every optimal branch and remove duplicates; the number of answers can be large.

Problem 4 · Boundary cases

What are the LCS length and sequence for (ABCD,EFGH), (empty string,ABC), and (AAAA,AA)?

Show solution

The first two pairs return length 0 and the empty sequence: there are no shared characters in the first pair and no characters available in the empty input. The third returns length 2 and AA. Matching positions must be used in increasing order, so the same character position cannot be reused.

Problem 5 · Convert one string into another

Using only single-character insertions and deletions, how many edits are needed to transform HEAP into PEA?

Show solution

An LCS is EA, with length 2. Keep these characters, delete H and the final P, then insert P at the beginning: 3 edits. In general, the minimum is m+n−2L because m−L characters must be deleted and n−L inserted. This formula does not apply unchanged when substitutions are permitted as a single edit.

Common mistakesDo not confuse prefix length i with character index i−1. A match adds 1 to the diagonal, not to the cell above. A mismatch takes a maximum; it does not reset the state to zero. Finally, reverse the traceback output before returning it.

13.10Exercises and checks

Use these questions to check both the computed answer and the reasoning behind it.

  1. Improve Fibonacci auxiliary space to O(1) using prev2, prev1, and current.
  2. Can DP improve a single factorial computation? No: the recursion has no overlapping subproblems. It can efficiently generate the whole series 0!,1!,…,m!.
  3. Can DP implement merge sort? Standard merge-sort subproblems are disjoint, not identical, so memoization adds no benefit.
  4. For each DP algorithm, identify the state, recurrence, base case, evaluation order, and returned state.
  5. Derive matrix-chain complexity from the length, start-index, and split-index loops.
Check your worked-example answers

F(5)=5. Knapsack returns profit 8 by selecting items 2 and 4 (total weight 8). Matrix-chain multiplication returns cost 76 with order A₁(A₂(A₃A₄)). A rod of length 8 returns revenue 22 using lengths 2 and 6.

A reliable DP checklistState precisely what each entry means. Establish base cases. Justify that the recurrence considers every legal choice. Evaluate dependencies first. Return the correct state and preserve decisions when the solution itself is required.
