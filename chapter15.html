Hashing

A key gives you a starting address. What happens when another key lands there too? Build a hash table, follow its probes, and see how deletion and probabilistic membership change the rules.

Explore as you readUse Step to follow each insertion. Compare collision strategies with the same keys, then test a Bloom-filter false positive.

15.1Why hashing?

Go to an address instead of scanning every element.

A hash table maps a key to a bucket or slot. Hash-table operations take expected O(1) time when hashing distributes keys well and the load stays controlled, with resizing amortized over many insertions. A single operation can still cost O(n). Computing the hash of a string also depends on its length.

Search structureTypical guarantee
Unsorted array or linked listO(n) worst-case search
Sorted array or balanced BSTO(log n) worst-case search
Hash tableExpected O(1), worst-case O(n)

Find the repeated characters

Change the text and watch the counts update.

Compare every pair

For each character, scan again to check for duplicates: O(n²) time. With a fixed character alphabet, repeated output can be avoided without a growing set.

Count once

A frequency table counts each character in one pass. A fixed array costs O(n+Σ) time and O(Σ) space. This activity uses a map so Unicode characters work too.

ASCII, byte values, and input length

Standard ASCII has 128 codes. A byte-indexed frequency array has 256 counters and can handle values 0…255. The string length n can be any size; it is not fixed at 256. The activity counts Unicode code points, which can differ from user-perceived characters such as joined emoji.

A fast calculation must also spread the keys.

Quick to compute

Well distributed

The load factor is α=n/m: stored keys divided by buckets or slots. A hash function works together with table capacity and the collision strategy.

Perfect hashing and unavoidable collisions

A perfect hash function has no collisions on a particular known key set. It need not be restricted to tiny sets, but constructing it is a different task from supporting arbitrary changing keys. If the possible key universe is larger than the table, a single mapping into its slots cannot be collision-free for every possible key.

15.5Open addressing

Keep every entry in the table. Change the route after a collision.

A table with m slots can store at most m entries. Practical implementations resize before it fills because probes become expensive at high load. A search follows the same probe sequence used for insertion.

Compare the same colliding keys

Insert 1, 11, 21, 31 in a ten-slot table, or enter your own sequence.

Current key —Slot probes 0Load α 0.0
    MethodProbe ruleWhat to watch
    Linear(h(k)+i) mod mPrimary clustering: contiguous occupied runs grow together.
    Quadratic(h(k)+c₁i+c₂i²) mod mKeys with the same home slot share a sequence: secondary clustering. Coverage depends on the parameters.
    Double hashing(h₁(k)+i·h₂(k)) mod mThe second hash chooses the stride. It must be nonzero and coprime to m for full coverage.
    Why this quadratic example can fail before the table is full

    Here c₁=0, c₂=1, and m=10. Starting at slot 1, i=0…9 visits 1,2,5,0,7,6,7,0,5,2: only six distinct slots. The seventh colliding key cannot be inserted, even though other slots are empty. This is a limitation of these parameters, not of every quadratic-probing scheme.

    The double-hash stride in this activity

    The activity chooses h₂(k) from [1,3,7,9], using k mod 4 as the list index. All four strides are coprime to 10, so each sequence visits all ten slots before repeating. This is a small teaching function. Good production choices also need suitable distribution. Double hashing does not eliminate every collision and is not universally the fastest strategy.

        15.7Bloom filters

        A “no” can be certain even when a “yes” is only a possibility.

        A standard Bloom filter stores a bit array and several hash functions. Insertion sets the key’s bit positions to 1. A query checks those same positions. It stores no original keys and can produce false positives.

        Three hashes, sixteen bits

        Add a word, test it, then try a known false positive.

        Recorded insertions: NoneBits set: 0 / 16

          Empty filter

          No words have been added.

          The small, deterministic hashes make shared bits easy to see. The recorded insertion list is shown only to verify the demonstration’s answers; the filter’s query uses the bits alone.

          Some tested bit is 0

          Definitely absent. With unchanged hash functions and no unsafe bit clearing, an inserted key cannot produce this result.

          All tested bits are 1

          Possibly present. Other inserted words may have set those same bits.

          Why a standard Bloom filter cannot simply delete

          Clearing a shared bit can make another inserted key appear absent, creating a false negative. Standard Bloom filters therefore do not support arbitrary deletion by clearing bits. Counting Bloom filters use counters instead. With appropriate hashes, more bits generally reduce false positives for a fixed number of insertions and hashes; a filling bit array makes positives less selective.

          15.8Static and dynamic hashing

              15.9Practice with hash sets

              Choose the stored key carefully: a character, a number, a node identity, or a complement.

              1. Remove duplicate characters

                Given a character array, remove duplicates using hashing.

                Example and approach

                BANANA → BAN, preserving the first occurrence. Keep a set of seen characters, append a character only on its first occurrence. Expected O(n) time and O(u) extra space for u distinct characters.

              2. Compare two unordered arrays as sets

                Check whether they contain the same distinct numbers.

                Example and approach

                [2,1,1] and [1,2] represent the same set. Build a hash set from each array and compare membership and set sizes. Duplicate counts do not matter. Expected O(n+m) time and O(u+v) extra space for their distinct elements.

              3. Detect a loop in a singly linked list

                Use hashing to check whether traversal revisits a node.

                Example and approach

                Store each node’s identity in a visited set. Reaching a stored identity means a cycle; reaching null means no cycle. Equal data values in different nodes do not imply a loop. Expected O(n) time and O(n) extra space for n distinct reachable nodes. Floyd’s algorithm is an O(1)-space alternative, but does not use hashing.

              4. Find a cross-set pair summing to K

                Find a∈A and b∈B such that a+b=K.

                Example and approach

                With A={1,4,8}, B={3,6,9}, and K=10, pairs (1,9) and (4,6) work. Store B in a hash set. For each a, check whether K−a is present. Expected O(|A|+|B|) time and O(|B|) extra space.
