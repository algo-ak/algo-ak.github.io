Chapter 10

Greedy Algorithms

A greedy algorithm always makes the choice that looks best at the moment. This chapter develops that idea through fractional knapsack, Huffman coding, job sequencing with deadlines, and the optimal merge pattern.

10.1Introduction to Greedy Algorithms

Core idea A greedy algorithm builds a solution step by step by choosing the best feasible option at the current stage. For problems with the greedy-choice property and optimal substructure, these choices produce a globally optimal solution.
From many solutions to an optimal solution
Optimization problems impose constraints; feasible solutions are filtered before the best one is chosen.
Maximize

Profit, reliability, trust, and efficiency.

Minimize

Cost, risk, and latency.

Greedy-choice property

A locally optimal choice can be committed to without preventing a globally optimal solution.

Optimal substructure

An optimal solution contains optimal solutions to its subproblems.

Why use it? When both properties hold, the greedy method often produces an efficient solution.

10.2Steps to Design a Greedy Algorithm

1 Choose a strategy

Decide the sorting rule, selection criterion, or priority.

2 Iterate in stages

Consider the input elements one by one in greedy order.

3 Check feasibility

Add a choice only when it keeps the partial solution feasible.

GREEDY(A):
    candidates = order_by_greedy_rule(A)
    solution = []

    for candidate in candidates:
        if feasible(candidate, solution):
            solution.append(candidate)

    return solution
Final step After all stages, return the constructed feasible solution.

def fractional_knapsack(items, capacity):
    for item in items:
        item.ratio = item.profit / item.weight

    items.sort(key=lambda item: item.ratio, reverse=True)
    total_profit = 0

    for item in items:
        if capacity == 0:
            break

        if item.weight <= capacity:
            capacity -= item.weight
            total_profit += item.profit
        else:
            total_profit += item.profit * (capacity / item.weight)
            break

    return total_profit

10.4Huffman Coding

Greedy compression Huffman coding is a greedy algorithm used for data compression. It assigns variable-length codes according to frequency: more frequent characters receive shorter codes. Depending on the data, it can save roughly 20% to 90% of storage.

2. Huffman solution approach

  1. Merge the two least frequent nodes into a new node whose frequency is their sum.
  2. Put the new node back and repeat until one root remains.
  3. Add 0 to every left edge.
  4. Add 1 to every right edge.
  5. Traverse from the root to each leaf to obtain its Huffman code.

10.5Building a Huffman Tree with a Priority Queue

  1. Create a binary-tree node for every character and frequency.
  2. Place the nodes in a priority queue—a min heap ordered by frequency.
  3. Extract the two minimum nodes, attach them to a new node, and insert their sum.
  4. Repeat until the queue contains one node: the root.
HUFFMAN(C):
    n = |C|
    Q = C
    for i = 1 to n - 1:
        allocate a new node z
        x = EXTRACT_MIN(Q)
        y = EXTRACT_MIN(Q)
        z.left = x
        z.right = y
        z.freq = x.freq + y.freq
        INSERT(Q, z)
    return EXTRACT_MIN(Q)  # the root is the only node left
Priority-queue construction for I:3, U:4, A:5, O:6, E:7
Lower frequency means higher priority.
A = 00 O = 01 E = 10 I = 110 U = 111
Why the printed codes can differ The queue contains E:7 and IU:7. Either may be extracted first. Also, the left and right children of any merged node may be swapped. These choices change the printed 0/1 patterns, but not the code lengths, prefix property, or weighted total of 57 bits.

10.6Job Sequencing with Deadlines

Problem Each unit-time job has a deadline and a profit earned only when the job finishes by that deadline. Schedule jobs to maximize total profit.
Applications

Operating-system task scheduling, project management, and manufacturing processes.

Capacity of the schedule

If the highest deadline is k, at most k unit-time jobs can be scheduled.

Brute force Trying all job permutations takes O(n!) time and is impractical for large n.

Greedy solution

  1. Sort the jobs in decreasing order of profit.
  2. For each job, place it in the latest empty slot that is no later than its deadline.
Schedule each job in the latest available slot
Sort by decreasing profit, then scan backward from each deadline.
Total profit: 0

Problem statement Given n sorted files with sizes S₁, S₂, …, Sₙ, merge them in pairs. Merging two files costs the sum of their sizes. Find the merge order with minimum total cost.
FileABCD
Size3020105

Greedy solution

  1. Insert all file sizes into a min heap (priority queue).
  2. Extract the two smallest files.
  3. Merge them; the merge cost is the sum of their sizes.
  4. Insert the merged file back into the heap.
  5. Repeat until one file remains; add every merge cost to the total.
Always merge the two smallest files first
A min heap keeps the next two files at the front of the priority queue.
Total merge cost: 0

Equal file sizes When equal-size files tie for the smallest values, either tied file may be chosen. Continue applying the two-smallest rule after every merge; an arbitrary unbalanced merge order is not generally equivalent.
Real-world applications Huffman coding, external sorting for large database datasets, and data-merge operations such as log-file merging and distributed computing.
Homework If the total file size is n and there are exactly four subfiles, what is the worst-case merging time in terms of n?
Reveal the answer

With total file size n and exactly four subfiles, there are three merges. Since four is constant, the worst-case merging time is Θ(n) in terms of n.
