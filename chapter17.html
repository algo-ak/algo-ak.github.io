Chapter 17

Branch and Bound: 0/1 Knapsack

Branch and bound explores include/exclude decisions, but uses an optimistic upper bound to avoid subtrees that cannot improve the best feasible solution already found.

Interactive chapterFollow the exact capacity-16 example from root bound 115 to the optimal profit 90. The visual trace shows the live-node priority queue, infeasible nodes, pruning, and the final selected items.

17.1The knapsack problem

Each item has a profit pᵢ and a weight wᵢ. Select items whose total weight does not exceed capacity W while maximizing total profit.

maximize   Σpᵢxᵢ    subject to   Σwᵢxᵢ≤W,   xᵢ∈{0,1}
Fractional knapsack

An item may be divided. Sorting by pᵢ/wᵢ and filling greedily gives an optimal solution.

0/1 knapsack

An item is taken completely or excluded. Backtracking, dynamic programming, and branch and bound are common approaches.

17.2Backtracking baseline

Backtracking performs depth-first search over the binary include/exclude decision tree. A branch is abandoned immediately when its total weight exceeds W, but many feasible combinations may still be explored.

ConceptBacktracking behavior
SearchDepth-first search through item decisions
BranchingInclude or exclude the current item
PruningAbandon a branch when its weight exceeds capacity
GoalBest profit among all feasible combinations
LimitationMay inspect nearly all 2ⁿ subsets
def backtrack(i, weight, profit):
    global best
    if weight > W:                 # infeasible branch
        return
    if i == n:
        best = max(best, profit)
        return
    backtrack(i + 1, weight + w[i], profit + p[i]) # include
    backtrack(i + 1, weight, profit)               # exclude

backtrack(0, 0, 0)
Why branch and bound helpsBacktracking prunes only infeasible paths. Branch and bound also prunes a feasible partial solution when even its most optimistic completion cannot beat the current best profit.

17.3Branch, bound, and prune

Branch

Create two subproblems: include the next item or exclude it.

Bound

Compute an optimistic upper bound on any solution below that node.

Prune

Discard an infeasible node or any node with bound≤current best.

A max-priority queue stores live nodes by bound. Best-first branch and bound expands the live node with the highest upper bound first, focusing work on the most promising region.

Correct pruning ruleIf node.bound≤bestProfit, no descendant of that node can improve the incumbent solution, so the entire subtree is safe to prune.

17.4The fractional upper bound

Starting after the node’s last decided item, fill the remaining capacity greedily. Add whole items while they fit, then add a fraction of the next item. This may be infeasible for 0/1 knapsack, which is exactly why it is an optimistic upper bound.

bound = profit so far + maximum fractional profit from the remaining capacity

17.7Brute-force and optimized algorithms

Recursive brute-force Python
def knapsack(values, weights, capacity, n):
    if n == 0 or capacity == 0:
        return 0
    if weights[n - 1] > capacity:
        return knapsack(values, weights, capacity, n - 1)
    include = values[n - 1] + knapsack(
        values, weights, capacity - weights[n - 1], n - 1)
    exclude = knapsack(values, weights, capacity, n - 1)
    return max(include, exclude)

values, weights, capacity = [40,30,50,10], [2,5,10,5], 16
print(knapsack(values, weights, capacity, len(values))) # 90
Best-first branch-and-bound Python
from dataclasses import dataclass
import heapq, itertools

@dataclass
class Node:
    level: int; profit: int; weight: int; bound: float

def upper_bound(node, items, capacity):
    if node.weight >= capacity: return 0
    profit, total, j = node.profit, node.weight, node.level + 1
    while j < len(items) and total + items[j][1] <= capacity:
        profit += items[j][0]; total += items[j][1]; j += 1
    if j < len(items):
        profit += (capacity-total) * items[j][0] / items[j][1]
    return profit

def branch_and_bound(values, weights, capacity):
    items = sorted(zip(values, weights), key=lambda x:x[0]/x[1], reverse=True)
    root = Node(-1, 0, 0, 0); root.bound = upper_bound(root, items, capacity)
    heap, order = [], itertools.count(); heapq.heappush(heap, (-root.bound,next(order),root))
    best = 0
    while heap:
        _,_,current = heapq.heappop(heap)
        if current.bound <= best: continue
        level = current.level + 1
        if level >= len(items): continue
        include = Node(level,current.profit+items[level][0],current.weight+items[level][1],0)
        if include.weight <= capacity: best = max(best,include.profit)
        include.bound = upper_bound(include,items,capacity)
        if include.bound > best: heapq.heappush(heap,(-include.bound,next(order),include))
        exclude = Node(level,current.profit,current.weight,0); exclude.bound = upper_bound(exclude,items,capacity)
        if exclude.bound > best: heapq.heappush(heap,(-exclude.bound,next(order),exclude))
    return best
Implementation detailThe heap entry includes a monotonically increasing tie-breaker so Python never needs to compare two Node objects when bounds are equal.

17.8Complexity analysis

OperationTime
Create rootO(1)
Compute one fractional boundO(n) in the direct implementation
Push or pop a live nodeO(log k), where k is queue size
Generate two childrenO(1)
Work per expanded nodeO(n+log k)
Total for m created/expanded nodesO(m(n+log m)) after O(n log n) sorting
Worst case: m=Θ(2ⁿ), so branch and bound remains exponential.

Bounding can dramatically reduce the explored nodes on many instances, but it does not change the worst-case exponential nature of 0/1-knapsack search.
